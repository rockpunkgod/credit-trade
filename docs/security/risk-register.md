# Initial security and privacy risk register

Last updated: 2026-09-01 (Asia/Shanghai)

This register includes both design-stage requirements and narrowly implemented sandbox controls. A “required control” is not implemented merely because it is listed; only evidence stated in the current-status column has been exercised.

| ID | Risk | Required control / test | Current status |
|---|---|---|---|
| SEC-01 | Cross-tenant access or object-ID confusion | Tenant-bound authorization at query and service boundaries; negative integration tests | OPEN |
| SEC-02 | Cross-market data, traffic, ledger or payment mixing | Market-scoped keys/accounts/deployments; deny cross-region fallback; isolation tests | OPEN |
| SEC-03 | SSRF through provider URLs, tools or callbacks | Registry allowlist, egress policy, DNS/IP validation, redirect limits, private-range denial | OPEN |
| SEC-04 | Malicious supplier response or key exfiltration | Supplier boundary, schema/size validation, secrets isolated from buyer/logs, adversarial tests | OPEN |
| SEC-05 | Forged or discrepant usage inflates cost | Authenticated/linked metering evidence, independent bounds, variance workflow and reconciliation | PARTIAL — buyers cannot submit usage; domain-separated HMAC coverage binds synthetic supplier/buyer attribution, provider endpoint, version-linked supply price, quote, usage, rating, delivered-output digest, full inference-ledger content and settlement. Tests reject catalog/identity edits, digest recomputation, cross-scope transplant, exact-record/Map-key changes, sparse/decorated arrays, newest-price deletion and settlement/checkpoint deletion or reordering while local heads/checkpoints remain intact. Usage is still a sandbox estimate; the supplier fixture is not real KYB, and provider evidence, variance and reconciliation remain open |
| SEC-06 | Duplicate, replayed or out-of-order webhook | Signature and timestamp validation, replay window, inbox uniqueness and state machine tests | OPEN |
| SEC-07 | Concurrent charge/refund/payout creates double financial effect | Serializable transaction design, idempotency, immutable entries and race/property tests | PARTIAL — inference uses an atomic rollback-protected journal/checkpoint batch; an opaque HMAC request code plus exact idempotency Map/scope and canonical inference/billing coverage protect replay, and concurrent idempotency is tested. A funded buyer is not inserted into the buyer/hash index until its journal checkpoint succeeds; the injected checkpoint-signer failure leaves zero identity or ledger residue. Durable database isolation, refund and payout races remain open |
| SEC-08 | Account takeover or MFA bypass | Phishing-resistant MFA for privileged roles, session hardening and recovery controls | OPEN |
| SEC-09 | Payout-account rebinding theft | Re-verification, cooling period, enhanced review and dual approval | OPEN |
| SEC-10 | Administrator abuse or unaudited balance/configuration change | Least privilege, two-person approval, authenticated configuration, append-only audit and no direct balance mutation | OPEN — a platform-policy seal detects tested unsealed edits to the in-process platform fee and quote lifetime before a new quote can be issued; balance replay and HMAC checkpoints use locale-independent balance ordering and detect tested direct balance/journal edits while trusted state remains intact; exact data validation also rejects forged record/Map placement and sparse/decorated arrays. This is not configuration approval: administrator authorization, dual control, external audit anchoring and process-compromise resistance are not implemented |
| SEC-11 | Prompt/output, identity, payment or key data leaks through observability | Data minimization, structured redaction, retention rules and log/snapshot/CI scans | PARTIAL — HTTP/state tests confirm raw API-key hashes, integrity key material, request codes, key IDs, seals and authentication tags are not returned, alongside existing API-key/prompt redaction; buyer records internally authenticate the stored API-key hash, and the idempotency record stores no plaintext prompt. Structured production logging, retention and complete CI/artifact scans remain open |
| SEC-12 | Dependency, build or CI supply-chain compromise | Lockfile, provenance, SBOM, signature/checksum and dependency/container/IaC scans | OPEN |
| SEC-13 | Cost amplification and denial of wallet/service | Input/concurrency/rate/budget/price bounds, circuit breakers and anomaly alerts | OPEN |
| SEC-14 | Unsupported production payment is unlocked by configuration | Server evidence gate, separation of duties, two-person approval, audit and bypass tests | OPEN |
| SEC-15 | Sanctions/KYC service outage admits risky activity | Fail-closed onboarding/top-up/payout controls and explicit degraded-mode runbook | OPEN |
| SEC-16 | Backup exposes data or cannot restore consistent ledger | Regional encrypted backups, access separation, point-in-time recovery and restore drills | OPEN |
| SEC-17 | HMAC key/process compromise, unanchored catalog deletion or coordinated policy/record/head/checkpoint rollback makes local integrity seals forgeable or incomplete | KMS/HSM custody, separation of duties, audited key rotation/revocation, authorized configuration, external supplier/endpoint inventory and price/settlement/checkpoint anchors, append-only/WORM storage and restore verification | OPEN — the sandbox uses a process-local ephemeral key plus an in-memory platform-policy seal, price/settlement heads and ledger-checkpoint histories. A price head detects newest-version deletion only while that head remains; endpoints have seals but no independent collection head, so deletion of an otherwise unreferenced endpoint is not generally detectable locally. HMAC is not encryption or a digital signature, does not survive restart as durable evidence, and cannot defend after accepted-key/process compromise or coordinated rollback/resealing of all local integrity state |

No Critical/High finding can be declared resolved until its control is implemented and the named evidence is executed.
